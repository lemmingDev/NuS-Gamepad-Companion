# Setup: from scaffold to running app

This repo holds everything hand-authored (`lib/`, `test/`, CI, docs). The
`android/`/`ios/` platform shells must be generated by your Flutter SDK
(they embed SDK-version-specific Gradle/Xcode wiring), then these files are
overlaid. Flutter SDK 3.22+ (stable channel), Android SDK for device builds.

## 1. Create the repo

```powershell
gh repo create <you>/NuS-Gamepad-Companion --public --clone
cd NuS-Gamepad-Companion
# copy the scaffold files from C:\Users\PPSHS VR\Downloads\NuS-Gamepad-Companion here
```

## 2. Generate platform shells

```powershell
flutter create --org dev.nuscompanion --project-name nus_gamepad_companion .
```

This creates `android/`, `ios/`, etc. Keep them as generated except below.

## 3. Apply the Android BLE setup

Merge `android/MANIFEST_AND_GRADLE_SNIPPETS.xml` into:

- `android/app/src/main/AndroidManifest.xml` — permissions + `bluetooth_le` feature
- `android/app/build.gradle` (or `.kts`) — `minSdk = 24`

## 4. Run

```powershell
flutter pub get
flutter analyze
flutter test
flutter run            # with a phone on USB (or an emulator with BLE caveats)
```

Flash any `examples/NuS/*` sketch, open the app, Scan → tap the
`ESP32 …` device → send `help`.

## 5. Installable builds

- Debug APK for sideloading: `flutter build apk --debug`
  (`build/app/outputs/flutter-apk/app-debug.apk`), or download the CI artifact.
- Signed release: create a keystore, add signing config + secrets, then
  `flutter build apk --release` / `flutter build appbundle`.
- iOS: `flutter build ios --no-codesign` only verifies compilation. Real
  devices need signing (Apple Developer Program) + TestFlight distribution.

## Troubleshooting

- **Empty scan**: Bluetooth off? Permissions denied? On Android ≤ 11 the
  location permission is required for BLE scanning — grant it. Don't
  rapid-fire Scan either: Android throttles frequent start/stop cycles and
  serves empty results — the app scans continuously until you tap Stop.
  If the board shows in nRF Connect but not here, it's app-side; if it's
  missing everywhere, the board isn't advertising (stale link — wait ~30s
  or power-cycle it).
- **Connects but no hello line**: the sketch needs a NuS subscriber greeting;
  send `help` manually. Check the sketch flashed is a NuS one.
- **`flutter analyze` complains about versions**: bump the caret deps in
  `pubspec.yaml` (`permission_handler`, `flutter_lints`) to current releases.
